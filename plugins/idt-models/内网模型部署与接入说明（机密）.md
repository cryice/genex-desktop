# 内网大模型部署与接入说明

> 适用范围：本项目（idt-product-prototype monorepo）中接入的**内网 GPU 推理模型**，包括 `Hunyuan3D-2.1`、各类 `Qwen` 系图像模型（Qwen-Image-2.1 补全、Qwen-Image-Edit 图生图）、`FLUX.2-klein-4B` 文生图，以及前置的分割服务（GroundingDINO + SAM2）。
>
> 一句话结论：这些模型**部署在独立的内网 GPU 服务器上**（由算法团队通过 Xinference / FastAPI 承载），本仓库的 `idt-model-server`（:8090）只是**调用方**。仓库内不含模型推理服务的部署代码，只含**接入与编排层**。

## 2. GPU 服务器上的模型是如何部署的

### 2.1 总体原则：调用与推理分离

Java 侧（`idt-model-server`）**本机不加载任何模型权重、不跑 Python 推理**。它只负责：提交任务、调度、调远程 GPU 服务的 HTTP 接口、回写结果。真正的推理发生在上面那几台 GPU 机器上，由算法团队维护。

### 2.2 Hunyuan3D 通过 Xinference 托管（66 / 75 节点）

- **Xinference 推理平台**提供 OpenAI 兼容的模型 API（`/v1/models` 列模型、`/v1/flexible/infers` 发起推理、`/models/{id}/requests/{rid}/abort` 取消）。
- **权重位置**：`/opt/idt/Hunyuan3D`（完整节点）。
- **异步加载**：Xinference 加载大模型耗时很长（Hunyuan3D 约 123s），因此**上架后不会立刻可用**。后端 `ModelProviderServiceImpl` 会轮询 `/v1/models`，直到该模型真实出现才把状态标成 `RUNNING`，否则标 `LAUNCHING`（自愈逻辑：`init()` 第 51–71 行建表、`syncModels()` 第 132 行同步、`launchModel()` 调 Xinference launch）。
- **节点亲和（worker_ip 固定）**：为避免把请求派到没有该模型权重的 worker，上架/同步时通过 `worker_ip` 字段把模型绑定到指定 Xinference 节点（如完整模型固定 66、shape 固定 75）。`ModelService` 结构里的 `workerIp` 字段即为该用途。
- **资源门禁**：GPU 节点暴露 `:18091/gpu/status` 探针，返回各类任务的剩余显存。后端调度器（配置在 `idt-model-server.yaml` 第 63–75 行）据此判断节点是否具备启动条件：
  - full 节点（66:18091）：`text-to-3d ≥ 14GB`、`texture ≥ 12GB`、`shape ≥ 10GB`
  - shape 节点（75:18091）：`shape ≥ 6GB`

### 2.3 Qwen 系与分割服务（61 / 66 节点）

- **Qwen-Image-2.1 补全服务**与**分割服务**都是独立的 HTTP 服务（FastAPI 风格），各自有 `/health`、`/v1/capabilities`、`/v1/segment`、`/v1/edit` 等接口，由算法团队在 61 / 66 上常驻部署。
- **概念设计编辑服务**（61:8090）同时承载 `FLUX.2-klein-4B`（文生图）与 `Qwen-Image-Edit`（图生图），统一 `POST /edit`，靠 `model` 字段区分模型。
- 这些服务的**地址与密钥**通过环境变量 / Nacos 注入（见第 3 节），token 文件不进 Git。

### 2.4 部署可配置性（运维视角）

- 新增一个 3D 生成模型：在 `application.yml` 的 `idt.ai.generation.models` 追加一条（或用前端"模型服务"页动态注册 Xinference 模型），无需改代码（`GenerationModelConfig` 注释明示）。
- 切换模型服务地址：改 `IDT_AI_XINFERENCE_BASE_URL`、`IDT_WORLDGEN_REMOTE_BASE_URL`、`IDT_WORLDGEN_COMPLETION_BASE_URL`、`IDT_AI_EDIT_BASE_URL` 等环境变量即可，无需重新打包。

## 3. 接入层：idt-model-server 如何连这些服务

`idt-model-server`（:8090，Spring Boot）是接入中枢，提供**两条接入通道**：

### 3.1 通道 A：写死在 Client 里的直接 HTTP 调用（RestTemplate）

每个内网模型对应一个 `@Component` 客户端，base-url / key 来自配置：

| -------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| `WorldGenHunyuanClient`    | 66 的 Xinference `/v1/flexible/infers` | `idt.ai.xinference.base-url` = `http://10.108.15.66:9997`，`api-key` = `sk-Hy3D21Api0001` |
| `WorldGenRemoteSegmenter`  | 66 的分割服务 `/v1/segment`                | `idt.worldgen.remote-base-url` = `http://10.108.15.66:18092`                             |
| `WorldGenQwenClient`       | 61 的 Qwen-Image-2.1 `/v1/edit`        | `idt.worldgen.completion-base-url` = `http://10.108.15.61:18093`，token 来自文件              |
| `ConceptDesignServiceImpl` | 61 的编辑服务 `/edit`                      | `IDT_AI_EDIT_BASE_URL` = `http://10.108.15.61:8090`                                      |

配置来源：`idt-model-server/src/main/resources/application.yml`（第 33–66 行）给出默认值，运行时用**环境变量**或 **Nacos** 覆盖（`idt-model-server.yaml` 第 54–75 行是部署环境示例）。

### 3.2 通道 B：数据库驱动的"模型供应商"抽象层

为了让模型可动态增删、前台下拉可配、可视化运维，另有一条通用通道：

- 两张表 `ai_model_provider`（供应商：Xinference / OpenAI 兼容 / LOCAL_OPENAI）与 `ai_model_registry`（模型明细），在 `ModelProviderServiceImpl.init()` 自动建表。
- `resolveInvocation(modelName)` 按模型名从库里查出 `base_url` + `api_key`（**AES-GCM 加密存储**，解密见 `decryptValue`），返回 `ModelInvocationConfig`。
- 前端"模型服务"页面可：测试连通性（`/test`）、刷新同步 Xinference 运行态（`/sync`）、上架/下架（`launch` / `terminate`）、按 `creation_route`（concept / geometry）过滤下拉项（`creationModels`）。
- 播种三个默认模型：`flux-2-klein-4b`、`qwen-image-edit`、`hunyuan3d-2.1`，统一挂在"66 Xinference 内部模型"供应商下（`ensureConceptModels`）。

## 4. 浏览器侧是如何调用这些模型的

浏览器**绝不直接访问内网 GPU 服务端口**。调用链是：

```
浏览器 (idt-portal / idt-mgnt, axios)
   │  统一走网关前缀 /idt-api/model
   ▼
API 网关 (路由到 idt-model-server :8090)
   │
   ▼
idt-model-server 控制器 (RestController)
   │  RestTemplate / ModelProvider 抽象层
   ▼
内网 GPU 推理服务 (Xinference / FastAPI / 分割服务)
```

### 4.1 场景生成链路（Portal 创作页）

- 前端路径固定为 **`/idt-api/model/api/v1/scenegen`**（任务书 12.3 节；Portal 只调网关相对路径，不直连 Model 服务端口）。源码：`idt-portal/.../scene/api/worldgen.ts` 第 32 行 `API_ROOT`。
- 后端控制器：`SceneGenController`（`@RequestMapping("/api/v1/scenegen")`）。典型接口：
  - `GET /capabilities` —— 前端据此判断是否可用、拿到上传限制与可用模型
  - `POST /uploads` —— 上传场景原图（落到 MinIO）
  - `POST /jobs` —— 创建生成任务（带 `X-Request-Id`、`X-Idempotency-Key` 幂等键）
  - `GET /jobs/{id}`、`GET /jobs/{id}/manifest` —— 轮询任务状态与产物清单
  - `POST /jobs/{id}/cancel`、`/retry`、`/exports` —— 取消 / 重试 / 导出 GLB·USDZ
- 后端收到任务后，由 **`WorldGenWorker`**（按 `IDT_WORLDGEN_WORKER_ENABLED` 启用的后台 worker）轮询领取、驱动完整流水线（见第 5 节）。

### 4.2 模型服务管理链路（mgnt 管理后台）

- 前端路径前缀 **`/idt-api/model/api/model-services`**（源码：`idt-mgnt/.../api/modelService.ts`）。
- 后端控制器：`ModelProviderController`（`/api/model-services`）、`XinferenceModelController`（`/api/xinference/models`）。
- 提供：供应商 CRUD（`/providers`）、模型增删改查与同步（`/models`、`/sync`）、上架/下架（`/launch`、`/terminate`）、单模型推理（`/models/{id}/infer`）。
- 此外还有概念设计（`ConceptDesignController` `/api/concept-design`，`GET /models`、`POST /generate`）与 AI 创作（`AiCreationModelController` `/api/ai-creation/models`、`AiCreationTaskController` `/api/ai-creation/tasks`、`AiCreationRecordController` `/api/ai-creation/records`）。

### 4.3 结论设计的两条输入形态

前端根据模型的 `conceptMode` 字段自动切换输入界面：

- `text2img`（如 FLUX）：只给文本提示框；
- `img2edit`（如 Qwen-Image-Edit）：需上传 1 张参考图 + 提示词；
- 几何生成模型（Hunyuan3D）`conceptMode = null`，走 Xinference 图生 3D 路径。

## 5. 端到端数据流（单图场景生成为例）

1. 用户在 Portal 上传场景图 → `POST /uploads` → 原图存 **MinIO**，返回 `image_ref`。
2. 创建任务 → `POST /jobs` → 任务写入 **MySQL**，状态 `queued`。
3. **`WorldGenWorker`** 轮询领取（`claimNextJob`），带 `lease`（租约 90s）+ 心跳（10s）续租；单机 GPU 并发固定 1。
4. **分割阶段**：调 **66 分割服务** `/v1/segment`，按对象抠图（GroundingDINO + SAM2）。
5. **补全阶段**：调 **61 Qwen-Image-2.1** `/v1/edit`，把残缺抠图补全成正面白底产品渲染图（`WorldGenWorker.completeImage`）。
6. **建模阶段**：调 **66 Xinference** `/v1/flexible/infers`（Hunyuan3D），逐对象生成 GLB；取消时同步调 `hunyuanClient.abort`（`runModeling`）。
7. 产物（GLB / 预览图）回写 **MinIO** + 更新 **MySQL** 任务状态为 `done`。
8. 浏览器轮询 `GET /jobs/{id}/manifest` 拿到带短期签名 URL（10 分钟有效）的产物清单并渲染。

## 7. 安全与可运维要点

- **数据不出境**：所有模型服务均为内网直连（10.108.x.x 段），不暴露公网。
- **密钥管理**：api-key 与环境变量注入；Qwen 服务的 token 走**文件**读取（`completionTokenFile`），不进 Git；供应商表里的 api_key 用 **AES-GCM** 加密落库。
- **降级与自检**：worker 启动前会做模型运行时自检（`selfCheckProfile`）；分割/补全/Qwen/Hunyuan3D 任一未就绪，worker 拒绝领取任务并在 `/api/v1/scenegen/runtime` 暴露状态，修复后无需重启即可恢复。
- **结果隔离**：MinIO 产物 URL 每次请求重新签发（10 分钟有效期），界面不缓存旧 URL。
- **幂等**：创建任务带 `X-Request-Id` + `X-Idempotency-Key`，避免前端重复提交/重试产生重复任务。

## 8. 外部客户端直接接入 66:9997（Xinference）实操指南

> 适用场景：在任意支持"OpenAI 兼容 / 自定义服务商"的客户端里，直接把 66 上的 Xinference 作为模型后端接入（**不走**本项目 `idt-model-server`，也**不走**网关）。本节由一次真实排障固化，可独立照做完成连接。

### 8.1 连接参数（照抄即可）

- **Base URL**：`http://10.108.15.66:9997/v1`
  - 末尾的 `/v1` 必须带；且**只能**接 `GET /v1/models`，不要写 `/models` 或重复拼 `/v1/v1/...`（均为 404）。
- **协议**：Xinference 是 OpenAI 兼容 API，但只开放 `/v1/models`（列模型）与 `/v1/flexible/infers`（推理）等，**不提供可用的 `/v1/chat/completions`**（其上的模型不是 LLM）。
- **认证方式**：API 密钥（`Authorization: Bearer`）。
- **API Key**：`sk-Hy3D21Api0001`（与 §3.1 `WorldGenHunyuanClient` 共用同一 key；来源 `idt-model-server/src/main/resources/application.yml:63`、`idt-scene-server/src/main/resources/application.yml:116`。**密钥勿外传、勿进 Git**）。

### 8.2 服务器上的真实模型清单（2026-10-14 快照，会随算法团队上下线变化）

通过 `GET /v1/models` 实测得到，四个实例 `model_type` 全部为 `flexible`，**没有任何 LLM**：

| model_uid         | 真实身份 (model_id)                         | 输入 → 输出                                                             | 后端承载                                                         | 客户端"用途"建议勾选                |
| ----------------- | --------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------- |
| `hunyuan3d-2.1`   | 腾讯 `tencent/Hunyuan3D-2.1`              | 文本 / 图像 / 多视图 → **带贴图 3D**（glb·fbx，可选仅几何）                           | 66 本机 direct launcher（权重 `/opt/idt/Hunyuan3D/Hunyuan3D-2.1`） | **3D**                     |
| `trellis2-4b`     | 微软＋清华 `microsoft/TRELLIS.2-4B`          | 单图 → **带 PBR 材质 3D**（GLB，最高 1536³；仅 `image_to_3d`，无 text/multiview） | 经 66 代理到 `61:8091/infer`（`trellis2_direct_launcher`）         | **3D**（客户端常误标为"图像"，按 3D 勾） |

> 注意：`qwen-image-edit` 与 `flux-2-klein-4b` **共用同一个后端** `61:8090/edit`，只靠 `mode` 字段区分（印证 §2.3）。  
> 若需要对话（LLM）能力，66 上没有，需让算法团队 `xinference launch` 一个 LLM（例：`xinference launch --model-name qwen2.5-instruct --model-type LLM`）。


### 8.3 关键陷阱（连不上的常见根因）
1. **没有语言模型**：66 上只有 3D / 图像生成模型，**没有任何 LLM**。若客户端按"聊天模型"协议（Chat Completions）探测/校验，必然失败。
2. **错误文案误导**：客户端报 "Could not reach the model endpoint" 未必是网络问题，真实可能是 **401 鉴权失败**。判定：`curl` 不带 key 返回 `{"detail":"Not authenticated"}`，key 错返回 `{"detail":"Could not validate credentials"}`，key 对返回 `200 + 模型列表`。
3. **路径拼错**：只有 `GET /v1/models` 有效；`/models`、`/v1models`、`/v1//models`、`/v1/v1/models`、`/v1/models/`（尾斜杠）均为 404。
4. **协议选错**：这 4 个模型是 `flexible` 类型，**不能走 `/v1/chat/completions`**（调用会报模型不支持）。做 3D / 图像要用 `POST /v1/flexible/infers`（见 8.4）。
5. **trellis2-4b 别当图像模型用**：它是图生 3D，客户端若识别成"图像"需手动改为 3D；用途勾错会导致调用失败。
6. **`args` 写错会被误判成"服务端没实现"**：`POST /v1/flexible/infers` 的 body 必须是 `{"model": …, "args": [载荷]}`。载荷没放进 `args` 列表时，`args` 为 `None`，请求在 xoscar actor 层就崩，返回
   `500 {"detail":"<xoscar.core.ActorRefMethod object at 0x…> argument after * must be an iterable, not NoneType"}`。
   **这条报错和"路由未实现"长得一模一样，且服务端 `/openapi.json` 对 `/v1/flexible/infers` 不声明 `requestBody`**（事实上 `/v1/chat/completions`、`/v1/completions` 也都不声明，故 OpenAPI 这点不能作为判断依据）。判别方法：加上 `args: [{}]` 再打一次，若 detail 变成 launcher 的原文（`[address=…] Hunyuan3D-2.1 requires one of: …`）就说明路由一直是好的，问题在 body。

### 8.4 正确调用方式（与本项目一致）
- **列模型（验证连通性）**：`GET /v1/models`（带 Bearer key）。
- **发起推理**：用 `POST /v1/flexible/infers`，body **必须是** `{"model": "<model_uid>", "args": [ <该模型自己的载荷> ]}`。
  - **`args` 必须存在、且必须是列表**：该路由把 `args` 解包进模型的 `infer`（`infer(*args, **kwargs)`）。把载荷放在别处（`parameters`、`kwargs`、或平铺在顶层）会让 `args` 为 `None`，请求在 actor 层就炸掉，**根本到不了模型**，返回约 15ms 内的同一个 500：
    ```
    500 {"detail":"<xoscar.core.ActorRefMethod object at 0x…> argument after * must be an iterable, not NoneType"}
    ```
    ⚠️ 这条报错**极易被误判为"该路由未实现"**。它不是：加上 `args` 之后每个 launcher 都会用自己的话回话（见下）。
  - **各模型的 `args` 载荷**：Hunyuan3D `{"image": "<base64>"}` / `{"text": "<prompt>"}` / `{"mv_image_front": …, "mv_image_back": …, "mv_image_left": …, "mv_image_right": …}`；TRELLIS.2 `{"image": "<base64>"}`；FLUX `{"prompt": …}`；Qwen-Image-Edit `{"prompt": …, "image": "<base64>"}`。
  - **图片编码两种都收**：裸 base64 或 `data:image/png;base64,…`（前缀会被归一化后再解码）。
  - **失败时服务端会给出可读原文**，例如 `[address=10.108.15.66:43101, pid=…] Hunyuan3D-2.1 requires one of: 'text' …, 'image' (base64) …, or 'mv_image_front'…`。**读这句话就能定位缺哪个字段**，不要重试同一个 body。
  - 具体参数结构亦可参考本项目 `WorldGenHunyuanClient`（Hunyuan3D）与 `ConceptDesignServiceImpl`（FLUX / Qwen 编辑）。**不要**用 `POST /v1/chat/completions`。
- **产物形态**：Hunyuan3D 返回 `{"status":"completed","format":"glb","has_texture":true,"model_base64":…,"obj_base64":…,"texture_image_base64":…,…}`（实测 55s、4.1MB GLB）；TRELLIS.2 返回 `{"model_base64": …}`（实测 120s、34.4MB GLB）；FLUX 返回 `{"image","image_base64"}`（单图）；Qwen-Image-Edit 返回 `{"front","left","top","perspective"}`（**四视图**，各一张 data URL）。
- **用途勾选汇总**：语言 = 0 个（都不勾）；图像 = `flux-2-klein-4b`、`qwen-image-edit`；3D = `hunyuan3d-2.1`、`trellis2-4b`；视频 = 0 个。

### 8.6 一句话排障流程
网络通？→ 看 `/v1/models` 返回码：401 = key 问题（用 8.1 的 key）；200 = 已连通但**别用 Chat 协议**，按 8.2 的用途勾选、用 8.4 的 `flexible/infers` 调用。若仍报"模型不支持 / 不是 chat" = 误选了 LLM 协议，需改用 flexible 或让算法团队补一个 LLM。若报 `argument after * must be an iterable, not NoneType` = **body 没把载荷放进 `args` 列表**（不是服务端缺实现，先把 `args` 写对再判断）；若报 `400 Client Error … for url: http://10.108.15.61:8091/infer` = 后端收到了请求但拒了图片（多半图片不是合法 PNG/JPEG，或格式不对）；若报 `500` 且 detail 是 `[address=…] … requires an image` = 请求已到达 launcher，只是缺字段。
